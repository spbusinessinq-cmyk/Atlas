2. DOCUMENT VAULT MUST SUPPORT REAL DOCUMENT VIEWING
==================================================

The Document Vault currently shows document rows, but the user also needs a real way to view/open the actual document.

Add a real document viewing flow.

Required behavior:
- each document row must support:
  - SELECT row -> populate right-side Document Inspector
  - VIEW / OPEN document -> open the actual file content
  - ANALYZE document

Do NOT make VIEW and SELECT the same thing.
They are separate actions.

Required document row actions:
- ANALYZE
- VIEW
- DOWNLOAD (if already supported)

Document viewing options:
Preferred:
- open an in-app document viewer in the CENTER PANEL
- preserve the left rail and right inspector
- center panel switches from document list to document viewer when VIEW is clicked

Acceptable fallback:
- open the stored file in a new browser tab if in-app preview is not feasible

Best approach:
Inside a case, Document Vault behaves like this:
- document list in center panel
- click row = show metadata in right inspector
- click VIEW = center panel shows actual document preview
- click BACK TO VAULT = return to document list

If the file is a PDF:
- render PDF preview if possible
- if preview is not feasible, provide a reliable open-in-new-tab behavior

If the file is not previewable:
show:
PREVIEW NOT AVAILABLE
Open or download the source file.

APPROVE

Behavior:
