ATLAS PASS 17 — INTELLIGENCE HARDENING + INVESTIGATION QUALITY FIRST

This pass is NOT a generic UI redesign pass.
Do NOT flatten ATLAS further.
Do NOT make it feel more like a SaaS admin dashboard.
The new boot screen is good — KEEP IT.
But the rest of the dashboard should stay tactical, dark, sharp, and intelligence-room oriented.
Prioritize extraction quality, entity relevance, case usefulness, and analyst trust.

PRIMARY GOAL:
Make ATLAS produce stronger, more relevant investigations automatically.
Right now the weakest point is intelligence quality:
- weak / irrelevant entity pulls
- money extraction still noisy
- auto-build sometimes creates empty / low-trust cases
- signal relevance is inconsistent
- weak docs still pollute the queue
Fix that first.

======================================================================
PART 1 — HARD RELEVANCE SCORING ENGINE
======================================================================

Create a true investigation relevance score per document.

Each ingested document should get a numeric score from 0–100 using:
- query term coverage
- title relevance
- body relevance
- investigative keyword density
- money keyword density
- government / institution keyword density
- local/location match
- domain quality
- body quality / extraction quality
- sports / entertainment / fluff penalties
- PR wire / press release penalty
- duplicate / near-duplicate penalty

Investigative boosts:
- contract
- grant
- funding
- budget
- allocation
- audit
- probe
- fraud
- corruption
- spending
- shelter
- housing
- homelessness
- procurement
- invoice
- nonprofit
- agency
- department
- oversight
- federal
- county
- state
- lawsuit
- records
- report
- program

Negative penalties:
- sports
- game
- coach
- player
- team
- playoff
- tournament
- score
- tv
- box office
- celebrity
- entertainment
- recipe
- lifestyle
- shopping
- travel
- review
- horoscope
- newsletter
- sponsored
- advertisement

Add labels:
- PRIORITY A
- PRIORITY B
- LOW SIGNAL
- NOISE

Do not allow LOW SIGNAL or NOISE docs to dominate seed cases.

======================================================================
PART 2 — ENTITY QUALITY FILTER 2.0
======================================================================

Current entity pulls are still too weak.
Build a stronger entity promotion filter.

Create entity trust scoring based on:
- appears in title
- appears in multiple docs
- appears near money language
- appears near program/agency keywords
- appears near investigative verbs
- appears as full multi-word proper noun
- appears in high-score docs only
- type compatibility with case topic

Penalty / suppress:
- single generic words
- obvious article fragments
- media artifacts
- week/day/month names
- sports names unless case topic is sports
- quote fragments
- press release filler
- “google news”, “question period”, “power play”, “every press”, etc.
- vague standalone nouns like “president”, “members”, “office”, “department” unless linked to a fuller name

Add stronger anti-noise entity blocklists and phrase filters.

Create a promoted_entity_score and use it for auto-build.

PART 3 — ENTITY NORMALIZATION / MERGE ENGINE
======================================================================

ATLAS needs to stop creating fractured duplicates.

Examples of what should merge:
- Los Angeles Homeless Services Authority
- LAHSA
- Los Angeles homeless services authority

- California Department of Housing and Community Development
- HCD

- Project Homekey
- Homekey

Build normalization rules:
- case-insensitive
- punctuation-insensitive
- acronym alias support
- singular/plural cleanup
- organization suffix cleanup
- remove possessive artifacts
- trim leading articles
- unify whitespace

Before promoting or graphing, try to resolve to canonical entity.
Store:
- canonical_name
- aliases[]
- confidence
- merge_reason

Do NOT over-merge people with organizations.

======================================================================
PART 4 — AUTO-BUILD INVESTIGATION ENGINE (REAL VERSION)
======================================================================

This is the main goal.

When user creates a seed investigation, ATLAS should automatically:
1. create case
2. generate search variants
3. search
4. ingest top sources
5. discard obvious junk
6. analyze usable docs automatically
7. score docs automatically
8. score entities automatically
9. promote strongest entities automatically
10. create starter graph automatically
11. generate case intelligence summary automatically

This should happen with minimal manual work.

Add a machine-readable case build status:
- seeded
- searching
- ingested
- analyzed
- promoted
- graphed
- summarized

Show whether auto-build succeeded or degraded.

If no usable docs exist:
- case should explicitly say BUILD DEGRADED
- explain why
- suggest next search actions
- do NOT pretend the case is valid

======================================================================

Upgrade the case summary so it reads like an analyst briefing, not placeholder text.

Generate:
- one-sentence overview
- document quality summary
- strongest entities
- strongest financial signals
- strongest timeline signals
- likely themes

NEXT QUERIES

- [entity] audit
- [entity] nonprofit payments

======================================================================
PART 6 — MONEY / FLOW EXTRACTION CLEANUP
======================================================================

Flow Trace is still polluted with irrelevant money text.

Improve financial extraction with:
- stronger proximity-to-investigative-keyword requirement
- reject ad copy / promo / pricing language
- reject sports contract fluff unless case topic is sports
- reject product / retail / consumer nonsense
- prefer program, budget, grant, contract, award, allocation, funding contexts

Extract:
- amount
- amountDisplay
- type (grant / funding / contract / settlement / allocation / budget / payment / salary / loan / transfer)
- subject entity
- counterparty entity
- sentence context
- source document
- confidence

If context is weak, do NOT promote it to Flow Trace.

======================================================================
