ATLAS PASS 5 — DOSSIER ENRICHMENT + CONTROLLED EXPANSION

Do NOT redesign the whole UI.
Do NOT rebuild the app.
Do NOT add mock data.
Do NOT implement full recursive autonomous expansion yet.

System:
RSR // ATLAS
Advanced Tracking & Link Analysis System

PRIMARY GOAL

Strengthen ATLAS as an investigative workstation by improving:
1. entity dossier usefulness
2. search precision for investigation targets
3. controlled expansion suggestions
4. warning color refinement (yellow -> orange)

After this pass, ATLAS should:
- make entity pages feel like real dossiers
- show why an entity matters
- help the user expand investigations intentionally
- improve precision for targeted searches like:
  "Highland Gardens Hotel" Los Angeles
  LAHSA hotel contracts
  Project Homekey Los Angeles

==================================================
1. WARNING COLOR REFINEMENT
==================================================

Replace the current yellow warning/pending color with a stronger orange tone.

Use orange for:
- pending detections
- triage counts
- warning banners
- extraction incomplete
- next-action caution states

Keep:
- red = critical/action
- teal/cyan = scan/intelligence
- green = approved
- orange = pending/caution

Do not leave mustard/yellow warning tones in the UI.

==================================================
2. DOSSIER ENRICHMENT
==================================================

Entity detail pages and the right-side entity dossier panel need to become much more useful.

For each approved entity, compute and display:

- entity name
- type
- aliases if any
- total mentions
- linked documents count
- first seen
- last seen
- related entities
- case membership
- mention excerpts/snippets
- source list

Improve the standalone entity page so it no longer feels empty.

Add useful sections such as:
- DOSSIER SUMMARY
- LINKED DOCUMENTS
- MENTION LOG
- RELATED ENTITIES
- RELATIONSHIPS
- TIMELINE APPEARANCES (if available, otherwise clean empty state)

If data is unavailable, do not fake values.
Use clean empty states like:
NO LINKED DOCUMENTS YET
NO TIMELINE ACTIVITY RECORDED

==================================================
3. LINKED DOCUMENTS ON ENTITY PAGES
==================================================

When an entity has mentions in documents, show those real linked documents clearly.

Each linked document item should display:
- document title
- source/domain
- ingest date
- mention count within that document
- quick action:
  OPEN DOCUMENT
  VIEW IN CASE

This is critical.
Right now entity pages do not feel connected enough to the evidence.

==================================================
4. MENTION LOG IMPROVEMENT
==================================================

Add a real Mention Log on entity pages and/or right-panel dossier view.

Each mention entry should show:
- source document
- snippet/context
- confidence
- mention status
- ingest date

Make the log dense and readable.
This is one of the most important parts of the dossier.

==================================================
5. RELATED ENTITY PANEL
==================================================

For each entity, compute related entities based on:
- shared documents
- repeated co-mentions
- approved co-occurrence

Show:
- related entity name
- type
- strength score or LOW/MEDIUM/HIGH label
- shared document count

Do NOT present these as confirmed factual relationships unless actually confirmed.
Use language like:
RELATED SIGNAL
CO-MENTIONED
POSSIBLE ASSOCIATION

6. SEARCH PRECISION IMPROVEMENT
==================================================

Improve WEB INGEST search behavior for investigative precision.

Current results are still too broad for some entity searches.

When query looks like a named entity, especially:
- quoted phrases
- title case phrases
- hotel/facility names
- agency names

Boost:
- exact title matches
- exact phrase matches
- matching locations
- investigation keywords:
  contract
  budget
  shelter
  homeless
  hotel
  housing
  authority
  department
  funding
  nonprofit
  program

Strongly demote irrelevant travel/lifestyle/listicle content when searching investigative targets.

Do NOT fabricate results.
Only improve sorting/filtering.

If useful, add a basic search mode:
- Standard
- Exact / Investigative

But only if lightweight.

==================================================
7. CONTROLLED EXPANSION SUGGESTIONS
==================================================

Do NOT auto-ingest everything yet.

Instead, add controlled expansion suggestions.

When an entity dossier is open, ATLAS should be able to suggest:
- related web searches
- related source queries
- related entities worth expanding

Examples:
For LAS PALMAS HOTEL:
- Search "Las Palmas Hotel Los Angeles contract"
- Search "Las Palmas Hotel Project Homekey"
- Search "Las Palmas Hotel homelessness program"

For LAHSA:
- Search "LAHSA hotel contracts"
- Search "LAHSA Project Homekey"
- Search "LAHSA interim housing providers"

Display these as:
EXPANSION SUGGESTIONS

Allow the user to click a suggestion and open WEB INGEST pre-filled with that query.

This is controlled expansion, not autonomous crawling.
