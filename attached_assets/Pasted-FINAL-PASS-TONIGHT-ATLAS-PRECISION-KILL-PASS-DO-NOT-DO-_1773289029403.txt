T001 — ADMISSION FIREWALL 2.0
FILE: entity-extractor.ts
==================================================

HARD RULE:
For serious investigative seeds, entities are NOT equally trustworthy across the page.

Implement a source-zone trust model:
- TITLE = strongest
- DEK / subheadline = strong
- FIRST 2–3 BODY PARAGRAPHS = medium-high
- mid-body = medium
- tail/body after paragraph 8 = weak
- sidebars / share rails / related links / footer / nav / promo / newsletter / “more stories” = reject

Create or strengthen extraction zones:
- title
- dek
- lead
- body
- tail
- sidebar
- footer
- related
- boilerplate
- unknown

Change entity admission rules:
1. AUTO-ADMIT candidates only if they appear in:
   - title OR
   - dek OR
   - lead OR
   - repeated in 2+ trustworthy zones
2. DOWNWEIGHT heavily if:
   - only appears in tail
   - only appears in one weak paragraph
   - only appears near social/share text
   - only appears in “more news”, “top stories”, “read more”, “watch”, “listen”, “newsletter”, “advertisement”, “sponsored”, etc.
3. HARD REJECT if candidate looks like:
   - merged names
   - line-stitched fragments
   - city/state/newsroom mashups
   - role/title + unrelated proper noun concat
   - unrelated locality cluster
   - cross-story bleed

ADD EXPLICIT PATTERN REJECTION FOR THESE TYPES OF FAILURES:
- STEVE BENEN JAMES COMER
- LOS ANGELESROANOKE CITY
- NEXT MIKE CRAPO
- MORE NEWS EAU CLAIRE CITY COUNCIL
- anything where:
  - 3+ title-case tokens stitched unnaturally
  - no normal punctuation spacing around merged capitalized segments
  - “MORE NEWS”, “NEXT”, “READ MORE”, “WATCH”, “LISTEN”, “TOP STORIES” prefix a candidate
  - candidate contains newsroom / navigation residue
  - candidate begins or ends with article chrome words

ADD a “merged-line artifact” rejection function.
ADD a “cross-story contamination” rejection function.
ADD a “navigation residue” rejection function.

FILE: web_ingest.ts

Rewrite promotion rules so the graph is cleaner.

NEW PROMOTION TIERS

T1_CONFIRMED:

- not rejected by artifact filters
- trust high enough

  - appears in title or dek

  - doc is PRIORITY_A

T2_HELD:
- anything plausible but not proven enough
- visible in triage, not graph

AUTO-REJECT:
- off-topic
- artifact
- navigation residue
- tail-only junk
- single common first name
- stitched locality phrases
- cross-story bleed

Add a hard rule:
For serious investigative seeds, if an entity appears in only 1 doc and does NOT appear in title/dek/lead, it cannot be auto-promoted.
