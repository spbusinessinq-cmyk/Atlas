PRIMARY GOALS

1. Remove duplicate source-opening buttons
2. Fix article-body extraction reliability
3. Add diagnostics so we can see why extraction is failing
4. Prevent false “extraction complete” states when only teaser/metadata text exists

========================================================
1. REMOVE DUPLICATE SOURCE BUTTONS
========================================================

In the document viewer / inspector UI,
OPEN SOURCE and OPEN ORIGINAL are redundant.

Keep only ONE action:
OPEN ORIGINAL

Remove OPEN SOURCE everywhere it duplicates the same destination.

Make sure:
- the remaining button opens the real article source URL
- no duplicate source-open buttons remain in the same document view

========================================================
2. ARTICLE BODY EXTRACTION DEBUGGING
========================================================

Extraction still appears to fail or return only shallow snippet content.

Add extraction diagnostics so we can understand exactly what is happening per document.

For each web-ingested document, record and expose:

- resolved source URL
- final fetched URL
- extraction status:
  SUCCESS
  PARTIAL
  FAILED
  WRAPPER_BLOCKED
- extracted text length
- paragraph count
- selector or extraction strategy used
- whether fallback extraction was used

Show this in the document inspector in a compact diagnostics section.

========================================================
3. DO NOT MARK TEASER TEXT AS SUCCESS
========================================================

Right now some docs appear to be treated as usable even though they likely only contain:
- title
- metadata
- short teaser
- partial wrapper body

Fix this.

A document should NOT be treated as fully extracted if:
- extracted text length is too short
- there are too few paragraphs
- body is mostly headline / metadata
- body is mostly boilerplate / teaser text

In those cases mark it as:
PARTIAL
or
FAILED

Do NOT show “EXTRACTION COMPLETE” unless real article text exists.

========================================================
4. IMPROVE ARTICLE BODY EXTRACTION
========================================================

Strengthen extraction from real source pages.

Expand / improve:
- article selectors
- paragraph aggregation
- main content container detection
- cleanup of nav/footer/related links text
- suppression of metadata-only extraction

When a page is valid but hard to parse, prefer:
- extracting real paragraph blocks
over
- using junk wrapper text

========================================================
5. ANALYSIS HANDOFF SAFETY
========================================================

NER / timeline / financial extraction should only run if extracted article text is actually usable.

If extraction status is:
FAILED
WRAPPER_BLOCKED
or severe PARTIAL with almost no body

Then:
- do not run normal entity extraction
- do not show fake “0 entities detected” as if it analyzed a full article
- instead show:
  “Analysis skipped: usable article body not recovered.”
